Quickstart

Set Up Development Environment
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

.. include:: /_snippets/set_up_dev_env.rst

The SIPL headers are expected to be installed on the host with NVIDIA SDK Manager when flashing the JetPack BSP.
When installing with SDK Manager, select all available optional packages.
For installation instructions, see the `JetPack Installation Guide <https://developer.nvidia.com/embedded/jetpack/downloads>`__.

If JetPack 7.2 was installed using an ISO image or with OTA updates, you can also install the SIPL and Multimedia APIs as follows:

.. code:: bash

   wget https://developer.nvidia.com/downloads/embedded/L4T/r39_Release_v2.0/release/Jetson_SIPL_API_R39.2.0_aarch64.tbz2
   wget https://developer.nvidia.com/downloads/embedded/L4T/r39_Release_v2.0/release/Jetson_Multimedia_API_R39.2.0_aarch64.tbz2
   sudo tar xjf Jetson_SIPL_API_R39.2.0_aarch64.tbz2 -C /
   sudo tar xjf Jetson_Multimedia_API_R39.2.0_aarch64.tbz2 -C /

JetPack 7.2 requires the ``isaac_ros_sipl_camera`` package from Isaac ROS 4.6 or later.
These package versions are not backward compatible with JetPack 7.1 or earlier.
For JetPack 7.1, use the package from Isaac ROS 4.3 through 4.5.

.. tabs::

      #. Launch the monocular camera node with default native NV12 output:

         .. code:: bash

            ros2 launch isaac_ros_sipl_camera sipl_camera.launch.py

   .. tab:: Eagle Stereo Camera

Data Flow
---------

The optional nodes shown below are added by the example launch files based on launch
arguments. See `Launch Files`_ for details.

.. mermaid::

   flowchart TD
      Camera["Camera / Stereo Camera"] -->|"GMSL2 or Ethernet (CoE)"| ISP["HW accelerated ISP"]
      ISP -->|"NvSciBuf (NVMM buffer)"| SiplCameraNode["SiplCameraNode /<br/>SiplStereoCameraNode"]
      SiplCameraNode -->|"NITROS, aligned stereo timestamps"| SyncOrDrop["NitrosCameraDropNode<br/>(stereo pair gating, optional)"]
      SiplCameraNode -.->|"NITROS (gating disabled)"| Raw(["image_raw / camera_info"])
      SyncOrDrop -->|"NITROS, complete pairs only"| Raw
      Raw -->|"NITROS (CUDA buffer)"| Converter["ImageFormatConverterNode<br/>(optional)"]
      Raw -->|"NITROS (CUDA buffer)"| Encoder["H.264 EncoderNode<br/>(optional, image_compressed)"]
      Converter -->|"NITROS (CUDA buffer)"| Rectify["RectifyNode<br/>(optional)"]
      Converter -->|"NITROS (CUDA buffer)"| Downstream["Downstream Nodes<br/>(SLAM, ESS, etc.)"]
      Rectify -->|"NITROS (CUDA buffer)"| Downstream

Message Timestamps
^^^^^^^^^^^^^^^^^^

By default, ``use_hw_timestamp`` is set to ``true`` and each image and its matching ``CameraInfo``
message are stamped with the capture start-of-frame (SOF) timestamp that SIPL APIs provides in the
Tegra timestamp counter (TSC) time domain.

The node uses a periodically calibrated offset to convert the timestamp from the TSC time domain to
the time domain of the node's ROS clock.

SOF and EOF in this context denote transport frame boundaries, not sensor exposure boundaries.
SOF occurs after exposure has started, but its exact relationship to exposure timing depends on the
sensor, shutter mode, and transport.
This SOF timestamp marks when the leading part of one transmitted image reaches the Jetson capture
path before the image payload and ISP processing.

* For GMSL2, the Video Input (VI)/NVCSI path records SOF as the image begins arriving from the
  deserializer.
* For CoE, the MGBE/RCE path records SOF as the first Ethernet packet marked as frame start arrives.

If ``use_hw_timestamp`` is ``false``, the node instead stamps with the current ROS clock time after
receiving the full frame after ISP processing.

For the transport paths, refer to the NVIDIA `GMSL architecture overview
<https://docs.nvidia.com/jetson/archives/r39.2/DeveloperGuide/SD/CameraDevelopment/SIPLFramework/SIPL-for-L4T/GMSL/GMSL-Architecture-Overview.html>`__
and `Camera-over-Ethernet overview
<https://docs.nvidia.com/jetson/archives/r39.2/DeveloperGuide/SD/CameraDevelopment/SIPLFramework/SIPL-for-L4T/CoE/CoE-Solution-Overview.html>`__.

Package Architecture
--------------------

Nodes
^^^^^

``SiplCameraNode``
""""""""""""""""""

Base node for monocular cameras. See `ROS Topics Published`_ and `ROS Parameters`_
for the full interface specification.

``SiplStereoCameraNode``
""""""""""""""""""""""""

Stereo camera node that extends ``SiplCameraNode``. See `ROS Topics Published`_ and
`ROS Parameters`_ for the full interface specification.

When running launch files, additional topics may be published depending on the launch arguments.
See the launch files section below for more details.

Launch Files
^^^^^^^^^^^^

The ``sipl_camera.launch.py`` and ``sipl_stereo_camera.launch.py`` launch files
conditionally add format conversion, rectification, H.264 encoding, and (for stereo)
frame-pair gating nodes based on launch arguments. The format conversion and
rectification nodes are from the :doc:`isaac_ros_image_proc </repositories_and_packages/isaac_ros_image_pipeline/isaac_ros_image_proc/index>` package, and the encoder node is from the :doc:`isaac_ros_h264_encoder </repositories_and_packages/isaac_ros_compression/isaac_ros_h264_encoder/index>` package.

When ``encoding_desired`` is set to a non-native format (anything other than
``nv12`` or ``nv24``), the launch file adds an ``ImageFormatConverterNode`` to
convert the output.

When ``enable_rectify`` is set to ``true``, the launch file adds a
``RectifyNode`` and automatically forces ``encoding_desired`` to ``rgb8`` if a
native format (``nv12``/``nv24``) was specified, because ``RectifyNode``
requires a standard image encoding.

When ``enable_encoding`` is set to ``true``, the launch file adds an
``EncoderNode`` that H.264-encodes the camera output and publishes it on
``image_compressed`` (per eye for stereo). The encoder consumes the same
``image_raw`` output as the other downstream nodes.

Color Conversion Limitation
"""""""""""""""""""""""""""

When the launch files convert native ``nv12`` output to a packed RGB or BGR
format, ``ImageFormatConverterNode`` uses ``yuv_color_spec=bt709``. SIPL ISP
buffers are allocated with ``NvSciColorStd_REC709_ER``, which is a full-range
BT.709 color standard. CV-CUDA ``AdvCvtColor`` supports the BT.709 color matrix,
but does not currently support the full-range ``REC709_ER`` variant. As a
result, converted images can have slightly different luma contrast than a true
full-range conversion. Native ``nv12`` and ``nv24`` output is unaffected.

If exact full-range color reproduction is required, subscribe to the native
camera output and convert it with a pipeline that supports ``REC709_ER``.

``sipl_camera.launch.py``
"""""""""""""""""""""""""

.. list-table::
    :header-rows: 1

    * - Launch Argument
      - Default
      - Description
    * - ``param_file``
      - ``eagle_mono.yaml``
      - Path to the YAML parameter file
    * - ``encoding_desired``
      - ``""`` (native)
      - Output encoding: ``nv12``/``nv24`` (native) or ``rgb8``, ``mono8``, etc. (converted)
    * - ``target_container``
      - ``sipl_camera_container``
      - Component container name
    * - ``camera_namespace``
      - ``""`` (root)
      - ROS namespace for the camera node and its topics. Set a distinct value per camera (along with a distinct ``target_container``) to run multiple cameras without topic or node-name collisions.
    * - ``enable_rectify``
      - ``false``
      - Enable image rectification through ``RectifyNode``
    * - ``enable_encoding``
      - ``false``
      - Enable H.264 accelerated encoding to ``image_compressed`` through the ``isaac_ros_h264_encoder`` ``EncoderNode``. ``true``/``false``.

**Pipeline variants**:

- **Native output** (default): ``SiplCameraNode``
- **Format conversion**: ``SiplCameraNode`` → ``ImageFormatConverterNode``
- **Rectification**: ``SiplCameraNode`` → ``ImageFormatConverterNode`` → ``RectifyNode``
- **Encoding**: ``SiplCameraNode`` → ``EncoderNode`` (publishes ``image_compressed``)

``sipl_stereo_camera.launch.py``
""""""""""""""""""""""""""""""""

.. list-table::
    :header-rows: 1

    * - Launch Argument
      - Default
      - Description
    * - ``param_file``
      - ``eagle_stereo.yaml``
      - Path to the YAML parameter file
    * - ``encoding_desired``
      - ``""`` (native)
      - Output encoding: ``nv12``/``nv24`` (native) or ``rgb8``, ``mono8``, etc. (converted)
    * - ``target_container``
      - ``sipl_camera_container``
      - Component container name
    * - ``camera_namespace``
      - ``""`` (root)
      - ROS namespace for the camera node and its topics. Set a distinct value per camera (along with a distinct ``target_container``) to run multiple cameras without topic or node-name collisions.
    * - ``enable_rectify``
      - ``false``
      - Enable image rectification through ``RectifyNode``
    * - ``enforce_stereo_pairs``
      - ``false``
      - Align left/right capture timestamps and gate stereo frame pairs (drop the pair if one of left/right never arrives). Enables the camera node's ``align_stereo_timestamps`` parameter and toggles the synchronization drop node. ``true``/``false``.
    * - ``enable_encoding``
      - ``false``
      - Enable H.264 accelerated encoding of the left and right images to ``image_compressed`` through the ``isaac_ros_h264_encoder`` ``EncoderNode``. ``true``/``false``.

**Pipeline variants**:

- **Native output** (default): ``SiplStereoCameraNode``
- **Format conversion**: ``SiplStereoCameraNode`` → ``ImageFormatConverterNode`` (left and right)
- **Rectification**: ``SiplStereoCameraNode`` → ``ImageFormatConverterNode`` (left and right) → ``RectifyNode`` (left and right)
- **Encoding**: ``SiplStereoCameraNode`` → ``EncoderNode`` (left and right, publishes ``image_compressed``)

**Stereo frame-pair gating with enforce_stereo_pairs enabled**:

When ``enforce_stereo_pairs`` is enabled, the launch inserts a ``NitrosCameraDropNode`` (stereo mode)
that exact-time-synchronizes the aligned left/right ``image_raw`` and ``camera_info`` set and
republishes only complete pairs. If one of the pair's frames is missing, both are dropped, so only
matched pairs are published. The camera's raw output is moved to ``*_unsynced`` topics, and the
synced pair keeps the canonical ``left/image_raw``, ``right/image_raw``, ``left/camera_info``, and
``right/camera_info`` topic names.

Verifying Stereo Camera Calibration
------------------------------------

Given the camera's calibration data, you may use the epipolar test :ir_repo:`isaac_ros_rectify_stereo_epipolar_test.py <isaac_ros_image_pipeline> <isaac_ros_image_proc/test/isaac_ros_rectify_stereo_epipolar_test.py>` in
:doc:`isaac_ros_image_proc </repositories_and_packages/isaac_ros_image_pipeline/isaac_ros_image_proc/index>`
package to validate that your stereo camera calibration produces accurately rectified
images based on epipolar line tests.

Several files are required to run the test and should be placed in the ``rectify_stereo`` test cases directory of the ``isaac_ros_image_proc`` package.

.. code-block:: text

    ${ISAAC_ROS_WS}/src/isaac_ros_image_pipeline/isaac_ros_image_proc/test/test_cases/rectify_stereo/


#. Refer to the quickstart section for the :doc:`isaac_ros_image_proc </repositories_and_packages/isaac_ros_image_pipeline/isaac_ros_image_proc/index>` package on how to clone and build the package.

#. Capture one left/right raw image pair of PNG files that contains a visible checkerboard pattern. For example, :ir_repo:`image_raw_right.png <isaac_ros_image_pipeline> <isaac_ros_image_proc/test/test_cases/rectify_stereo/stereo_chessboard0/image_raw_right.png>`

#. Create test configuration JSON files for the left and right camera respectively: ``image_raw_left.json`` and ``image_raw_right.json``. These files should reference the PNG files and include the checkerboard inner-corner grid size (rows x columns). For example, :ir_repo:`image_raw_right.json <isaac_ros_image_pipeline> <isaac_ros_image_proc/test/test_cases/rectify_stereo/stereo_chessboard0/image_raw_right.json>`

   .. note::

      The checkerboard size must use inner-corner counts (for example, a 10x7
      square grid uses a 9x6 inner-corner size).

#. Create camera info JSON files for left and right camera respectively: ``camera_info_left.json`` and ``camera_info_right.json``. For example, :ir_repo:`camera_info_right.json <isaac_ros_image_pipeline> <isaac_ros_image_proc/test/test_cases/rectify_stereo/stereo_chessboard0/camera_info_right.json>`

#. Place all the PNG and JSON files in the ``rectify_stereo`` test cases directory of the ``isaac_ros_image_proc``
   package:

   .. code-block:: bash

       # From the workspace root
       mkdir ${ISAAC_ROS_WS}/src/isaac_ros_image_pipeline/isaac_ros_image_proc/test/test_cases/rectify_stereo/sipl_stereo_camera
       cp <your_files> ${ISAAC_ROS_WS}/src/isaac_ros_image_pipeline/isaac_ros_image_proc/test/test_cases/rectify_stereo/sipl_stereo_camera

#. Build the ``isaac_ros_image_proc`` package after placing all the files:

   .. code-block:: bash

       colcon build --packages-up-to isaac_ros_image_proc
       source install/setup.bash

#. Run the test:

   .. code-block:: bash

       colcon test --packages-select isaac_ros_image_proc \
           --event-handlers console_direct+ \
           --ctest-args -R isaac_ros_rectify_stereo_epipolar_test

#. Verify the test results. Passing the test indicates that the calibration accuracy is satisfactory. If the test fails, downstream packages that consume the rectified images may still function, but with degraded performance depending on your application's requirements.

.. note::

    A well-rectified pair has horizontal epipolar lines with sub-pixel mean error (less than 0.5 px) and max error under
    approximately 1-2 px.

      - Stereo rig base frame
    * - ``left_camera_frame_name``
      - ``string``
      - ``stereo_camera_left``
      - Left camera frame
    * - ``right_camera_frame_name``
      - ``string``
      - ``stereo_camera_right``
      - Right camera frame
    * - ``right_camera_info_url``
      - ``string``
      - ``""``
      - Path to right camera calibration file
    * - ``align_stereo_timestamps``
      - ``bool``
      - ``false``
      - When ``true``, the timestamp for hardware-synced stereo left/right pairs (capture times within ``max_timestamp_diff_us``) is overridden with the earlier timestamp of the pair in order to stamp with identical timestamps. This is lock-free without blocking. Requires stereo cameras and ``use_hw_timestamp`` true.
    * - ``max_timestamp_diff_us``
      - ``double``
      - ``500.0``
      - In-sync window (microseconds) for ``align_stereo_timestamps``. Pairs farther apart keep their own timestamps and are deemed out of sync. This should be less than half the frame interval. Camera config and transport dependent threshold.
    * - ``expected_fps``
      - ``double``
      - ``30.0``
      - Expected capture frame rate, used only to bound the out-of-sync detection window for ``align_stereo_timestamps``. Does not change the publish rate.

GMSL Parameters
"""""""""""""""

These parameters apply when the platform configuration uses a GMSL transport (for example, the Hawk stereo camera).

.. list-table::
    :header-rows: 1

    * - ROS Parameter
      - Type
      - Default
      - Description
    * - ``link_mask``
      - ``int``
      - ``0x0001``
      - Each connected camera occupies one link: ``0x0001`` = channel 0,
        ``0x0002`` = channel 1, ``0x0004`` = channel 2, ``0x0008`` = channel 3.

.. note::

   **Only one GMSL camera can stream at a time.** ``link_mask`` must select
   exactly one link, and only one SIPL camera node can run on the system at
   once — a second concurrent node fails during SIPL platform configuration
   (``SetPlatformCfg``). Enabling multiple links in a single node is also not
   supported. Switch cameras by changing ``link_mask`` and relaunching.

Camera Calibration Overrides
^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Provide calibration files using ``package://`` or ``file://`` URLs. Example
calibration files are available in the package ``config/`` directory for quick
testing.

The following example shows how to set the calibration file in a YAML
parameter file:

.. code-block:: yaml

    sipl_camera:
      ros__parameters:
        camera_info_url: "package://isaac_ros_sipl_camera/config/mock_mono_camera_info.yaml"

Troubleshooting
---------------

Isaac ROS Troubleshooting
^^^^^^^^^^^^^^^^^^^^^^^^^

For solutions to problems with Isaac ROS, see :doc:`troubleshooting </troubleshooting/index>`.

SIPL CoE Camera Not Found
^^^^^^^^^^^^^^^^^^^^^^^^^^

For any issues with CoE camera detection, see the
:doc:`Eagle CoE Stereo Camera Setup </getting_started/sensors/eagle_setup>` guide.

SIPL GMSL Camera Produces No Frames
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Symptom
"""""""

The SIPL camera node initializes (``SIPL Camera initialized``) but no frames arrive, and after
``first_frame_timeout_s`` (default 5 s) the node fails with:

.. code:: text

   [FATAL] [sipl_stereo_camera]: [left] No frames from sensor 0 within 5.0s. Verify the camera connection.

Solution
""""""""

The Jetson might not be booted with the correct camera device tree. Re-run the readiness checks in
the :doc:`Hawk GMSL Stereo Camera Setup </getting_started/sensors/hawk_setup>` guide and confirm
that ``v4l2-ctl --list-devices`` reports ``ar0234``. Also confirm that the GMSL distribution board
has 12 V power and that the camera is on the channel corresponding to the ``link_mask`` parameter.

HSB fails to initialize with error "Address already in use"
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Symptom
"""""""

Unable to bind to initialize HSB and configure the HSB transport driver. You see the following error message:

.. code:: bash

   [HSB] Error configuring driver: bind failed with errno=98: "Address already in use"

Solution
""""""""

Another Holoscan instance may still be running. Check and stop it:

.. code:: bash

    ps aux | grep hololink

If there is output, kill the process if it is safe to do so:

.. code:: bash

    kill -9 <pid>

SIPL Headers or Libraries Not Found
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Symptom
"""""""

You see the following error message when building the package:

.. code-block:: text

    CMake Error: SIPL headers not found at: /usr/src/jetson_sipl_api/sipl/include

Solution
""""""""

1. Install the SIPL libraries through NVIDIA SDK Manager.

2. Verify that the SIPL libraries and headers are present:

   .. code-block:: bash

       ls /usr/lib/aarch64-linux-gnu/nvidia/libnvsipl*
       ls /usr/src/jetson_sipl_api/sipl/include/

Invalid MAC or IP Address Format
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Symptom
"""""""

.. code-block:: text

    Invalid MAC address format, expected XX:XX:XX:XX:XX:XX
    Invalid IP address format, expected XXX.XXX.XXX.XXX

Solution
""""""""

- Make sure to retrieve the CoE camera's specific MAC and IP addresses. Refer to the :doc:`Eagle CoE Stereo Camera Setup </getting_started/sensors/eagle_setup>` guide for instructions.
- Use colon-separated hex format for MAC addresses: ``8c:1f:64:6d:70:03``
- Use dotted decimal format for IP addresses: ``192.168.1.2``
- Verify that the addresses match the camera documentation or EEPROM data.

HSB ID Mismatch
^^^^^^^^^^^^^^^

Symptom
"""""""

.. code-block:: text

    No matching transport found for override: hsb_id=X
    No matching camera found for override: hsb_id=X

Solution
""""""""

1. Verify that the ``hsb_id`` parameter matches the platform configuration.
2. Check the HSB ID in the camera system config.
3. For VB1940, the default HSB ID is typically ``0``.
4. Verify that the HSB ID matches across transport and camera configuration.
