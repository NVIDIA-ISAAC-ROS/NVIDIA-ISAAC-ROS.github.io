Quickstart#

Set Up Development Environment#

  1. Set up your development environment by following the instructions in getting started.

  2. (Optional) Install dependencies for any sensors you want to use by following the sensor-specific guides.

    Note

    We strongly recommend installing all sensor dependencies before starting any quickstarts. Some sensor dependencies require restarting the development environment during installation, which will interrupt the quickstart process.

The SIPL headers are expected to be installed on the host with NVIDIA SDK Manager when flashing the JetPack BSP. When installing with SDK Manager, select all available optional packages. For installation instructions, see the JetPack Installation Guide.

If JetPack was installed or updated using an ISO image or with OTA Debian updates, you also need to install or update the SIPL and Multimedia APIs as follows:

wget https://developer.nvidia.com/downloads/embedded/L4T/r39_Release_v2.0/release/Jetson_SIPL_API_R39.2.1_aarch64.tbz2
wget https://developer.nvidia.com/downloads/embedded/L4T/r39_Release_v2.0/release/Jetson_Multimedia_API_R39.2.1_aarch64.tbz2
sudo tar xjf Jetson_SIPL_API_R39.2.1_aarch64.tbz2 -C /
sudo tar xjf Jetson_Multimedia_API_R39.2.1_aarch64.tbz2 -C /

JetPack 7.2 requires the isaac_ros_sipl_camera package from Isaac ROS 4.6 or later. For JetPack 7.1, Isaac ROS 4.3 through 4.5 are compatible.

Build isaac_ros_sipl_camera#

  1. Activate the Isaac ROS environment:

    isaac-ros activate

  2. Install the prebuilt Debian package:

    sudo apt-get update

    sudo apt-get install -y ros-lyrical-isaac-ros-sipl-camera

  1. Install Git LFS:

    sudo apt-get install -y git-lfs && git lfs install

  2. Clone this repository under ${ISAAC_ROS_WS}/src:

    cd ${ISAAC_ROS_WS}/src && \
   git clone -b release-5.1 https://github.com/NVIDIA-ISAAC-ROS/isaac_ros_sipl_camera.git isaac_ros_sipl_camera

  3. Activate the Isaac ROS environment:

    isaac-ros activate

  4. Use rosdep to install the package’s dependencies:

    sudo apt-get update

    rosdep update && rosdep install --from-paths ${ISAAC_ROS_WS}/src/isaac_ros_sipl_camera/isaac_ros_sipl_camera --ignore-src -y

  5. (Optional) Replace the mock calibration files if you have the camera’s calibration data. See section on Camera Calibration Overrides for more details. The configuration uses mock calibration files by default.

  6. Build the package from source:

    cd ${ISAAC_ROS_WS} && \
   colcon build --symlink-install --packages-up-to isaac_ros_sipl_camera --base-paths ${ISAAC_ROS_WS}/src/isaac_ros_sipl_camera/isaac_ros_sipl_camera

  7. Source the ROS workspace:

    Note

    Make sure to repeat this step in every terminal created inside the Isaac ROS environment.

    Because this package was built from source, the enclosing workspace must be sourced for ROS to be able to find the package’s contents.

    source install/setup.bash

Run Launch File#

  1. Launch the monocular camera node with default native NV12 output:

    ros2 launch isaac_ros_sipl_camera sipl_camera.launch.py

  1. Launch the Eagle stereo camera with default native NV12 output:

    The default parameter file targets the Eagle VB1940 camera with eagle_stereo.yaml so no argument is needed.

    Note

    The SIPL VB1940_Stereo platform configuration enables synchronized stereo capture. In JetPack 7.2.0, a known bug corrupts the right edge of the image in this configuration. This bug is fixed in the JetPack 7.2.1 driver packages. A separate known issue remains where the left and right frames from the same capture can intermittently report capture timestamps about 18 ms apart, which interferes with stereo pairing. Until this issue is fixed, eagle_stereo.yaml sets platform_config to VB1940, which runs the sensors as independent pipelines.

    ros2 launch isaac_ros_sipl_camera sipl_stereo_camera.launch.py

  1. Launch the Hawk stereo camera with default native NV12 output and stereo frame-pair gating enabled:

    The hawk_stereo.yaml parameter file defaults to 0x0001, which assumes the Hawk is connected to channel 0. See GMSL Parameters for more details.

    ros2 launch isaac_ros_sipl_camera sipl_stereo_camera.launch.py \
    param_file:=$(ros2 pkg prefix isaac_ros_sipl_camera)/share/isaac_ros_sipl_camera/config/hawk_stereo.yaml \
    enforce_stereo_pairs:=true

Complete the Sensing Thor GMSL2 Camera Setup, then select the supplied parameter file for the cameras you want to run. Refer to Sensing S56C and SHF3L for the complete selection table.

Launch the S56C stereo camera:

ros2 launch isaac_ros_sipl_camera sipl_stereo_camera.launch.py \
   param_file:=$(ros2 pkg prefix isaac_ros_sipl_camera)/share/isaac_ros_sipl_camera/config/s56c_stereo.yaml \
   query_config:=trd1_g2a \
   enforce_stereo_pairs:=true

Launch one SHF3L camera on CAM2:

ros2 launch isaac_ros_sipl_camera sipl_camera.launch.py \
   param_file:=$(ros2 pkg prefix isaac_ros_sipl_camera)/share/isaac_ros_sipl_camera/config/shf3l_mono.yaml \
   query_config:=trd1_g2a

Use shf3l_mono_cam3.yaml instead to select CAM3.

Multi-camera capture on Jetson Thor with JetPack 7.2 has been validated in both the default 120W mode and MAXN with clocks locked. For a consistent setup, use MAXN and lock clocks on the Jetson host before launching:

sudo nvpmodel -m 0
sudo jetson_clocks

Reapply sudo jetson_clocks after reboot or changing the power mode as this does not persist.

This avoids a known capture timeout issue when load is high while multiple cameras are streaming.

Launch the complete mixed-camera rig or a subset described by a copied parameter file:

ros2 launch isaac_ros_sipl_camera sipl_multi_camera.launch.py \
   param_file:=$(ros2 pkg prefix isaac_ros_sipl_camera)/share/isaac_ros_sipl_camera/config/s56c_shf3l_mixed.yaml \
   query_config:=trd1_g2a

Set query_config to match your adapter. Refer to Other Thor GMSL Adapters for the supported configurations.

  1. Launch the stereo camera with RGB8 format conversion and image rectification:

    ros2 launch isaac_ros_sipl_camera sipl_stereo_camera.launch.py \
    encoding_desired:=rgb8 enable_rectify:=true

Message Timestamps#

By default, use_hw_timestamp is set to true and each image and its matching CameraInfo message are stamped with the capture start-of-frame (SOF) timestamp that SIPL APIs provides in the Tegra timestamp counter (TSC) time domain.

The node uses a periodically calibrated offset to convert the timestamp from the TSC time domain to the time domain of the node’s ROS clock.

SOF and EOF in this context denote transport frame boundaries, not sensor exposure boundaries. SOF occurs after exposure has started, but its exact relationship to exposure timing depends on the sensor, shutter mode, and transport. This SOF timestamp marks when the leading part of one transmitted image reaches the Jetson capture path before the image payload and ISP processing.

  • For GMSL2, the Video Input (VI)/NVCSI path records SOF as the image begins arriving from the deserializer.

  • For CoE, the MGBE/RCE path records SOF as the first Ethernet packet marked as frame start arrives.

If use_hw_timestamp is false, the node instead stamps with the current ROS clock time after receiving the full frame after ISP processing.

For the transport paths, refer to the NVIDIA GMSL architecture overview and Camera-over-Ethernet overview.

Package Architecture#

Nodes#

SiplCameraNode#

Base node for monocular cameras. See ROS Topics Published and ROS Parameters for the full interface specification.

SiplStereoCameraNode#

Stereo camera node that extends SiplCameraNode. See ROS Topics Published and ROS Parameters for the full interface specification.

SiplMultiCameraNode#

Node for an explicitly selected set of cameras sharing one SIPL platform, typically a multi-camera or mixed-sensor rig, also extending SiplCameraNode. Instead of the fixed left/right pipelines of the stereo node, it takes an ordered cameras list and a camera.<name>.* block per camera, and publishes each camera under its own <name>/ topic prefix. Any number of the cameras can be grouped into synchronized stereo_pairs.

A single node is required rather than one process per camera: SIPL takes exclusive ownership of the deserializer, so a second SetPlatformCfg() in another process fails. Only SIPL capture is constrained this way — downstream rectification, conversion and encoding nodes can still run in separate containers, fed by the per-camera topics.

The multi-camera node can run one camera or one stereo pair, but use SiplCameraNode or SiplStereoCameraNode for those common cases. They select their sensors automatically and need no explicit sensor IDs. Use one SiplMultiCameraNode for a subset of a shared-deserializer platform or for a mixed-sensor rig.

When running launch files, additional topics may be published depending on the launch arguments. See the launch files section below for more details.

Camera-Specific Configuration#

Sensing S56C and SHF3L#

Complete the Sensing Thor GMSL2 Camera Setup before using these configurations. Pass query_config:=trd1_g2a for the Sensing SG8A_AGTH_G2Y_A1 adapter. Refer to Other Thor GMSL Adapters for the other supported adapter configurations.

The package includes s56c_shf3l_mixed_trd1_g2a.json for convenience. This file is an unchanged copy of query/trd1_g2a/s56c_shf3l_mixed.json from the Sensing JetPack 7.2 driver package. Treat the JSON from the downloaded Sensing driver package as authoritative.

Update the Bundled Sensing JSON#

If the vendor JSON differs from the package copy, replace the package copy with the vendor file. Set SENSING_DRIVER_PACKAGE to the downloaded driver package directory on the Jetson host.

Replace the source copy on the host, then rebuild the package using the source-build procedure above:

export SENSING_DRIVER_PACKAGE=/absolute/path/to/TRD1_G2A_AGX_THOR_SIPL_JP7.2_L4TR39.2
cp "${SENSING_DRIVER_PACKAGE}/query/trd1_g2a/s56c_shf3l_mixed.json" \
   "${ISAAC_ROS_WS}/src/isaac_ros_sipl_camera/isaac_ros_sipl_camera/config/s56c_shf3l_mixed_trd1_g2a.json"

Stage the vendor JSON in the Isaac ROS workspace on the host before activating the environment:

export SENSING_DRIVER_PACKAGE=/absolute/path/to/TRD1_G2A_AGX_THOR_SIPL_JP7.2_L4TR39.2
cp "${SENSING_DRIVER_PACKAGE}/query/trd1_g2a/s56c_shf3l_mixed.json" \
   "${ISAAC_ROS_WS}/s56c_shf3l_mixed_trd1_g2a.json"

Inside the activated environment, replace the installed copy:

export SIPL_CAMERA_SHARE="$(ros2 pkg prefix isaac_ros_sipl_camera)/share/isaac_ros_sipl_camera"
sudo install -m 0644 \
   "${ISAAC_ROS_WS}/s56c_shf3l_mixed_trd1_g2a.json" \
   "${SIPL_CAMERA_SHARE}/config/s56c_shf3l_mixed_trd1_g2a.json"

A package upgrade or development-container recreation replaces this file. Repeat the install command when either occurs if the packaged and vendor versions still differ. The staged workspace copy remains on the host.

The supplied S56C_1_SHF3L_2 platform describes the fixed wiring in the Sensing Thor setup guide. Selecting a subset of cameras in that layout requires only a YAML parameter-file change. If the physical wiring, virtual channels, or sensor IDs differ, add a separately named platform JSON instead of changing the vendor file.

For a multi-camera subset, copy s56c_shf3l_mixed.yaml and keep these fields consistent:

  1. Set link_mask from the table.

  2. Set cameras to the names whose sensor IDs are enabled. The supplied blocks map head_left and head_right to S56C sensor IDs 0 and 1, wrist_left to CAM2 sensor ID 2, and wrist_right to CAM3 sensor ID 3.

  3. Keep stereo_pairs: ["head_left,head_right"] and align_stereo_timestamps: true when the S56C is selected. Use an empty stereo_pairs list and set align_stereo_timestamps: false for SHF3L-only selections.

  4. Keep the S56C NITO path when the S56C is selected. Set nito_file: "" for SHF3L-only selections.

Use the Sensing GMSL2 Cameras tab in Run Launch File to launch the selected configuration.

The Isaac ROS YAML files describe camera selection (S56C_1_SHF3L_2), not a specific deserializer chip. The launch argument query_config selects a bundled SIPL query JSON (platform_config_file) and the matching link_mask layout:

  • max96724 — one MAX96724

For the systems that support deserializer-generated frame sync, use fsyncMode: osc_manual. Leave enable_fsync_restart false when the Tegra frame sync block is not wired as the source on these adapters.

YUV Capture Pipelines and ISP Bypass#

Most SIPL cameras are RAW sensors processed by the Tegra ISP. YUV cameras such as the SHF3L instead have an on-sensor ISP and deliver YUV422 (UYVY) frames, so the Tegra ISP is bypassed entirely: frames are taken from the SIPL capture (ICP) output and converted to nv12 on the GPU before publishing. Such pipelines need no NITO file and no auto-control plugin.

Pipelines select their source automatically from the platform configuration: sensors whose capture input format is YUV422 publish from capture, and everything else goes through ISP0. Capture pipelines support nv12 only; a capture pipeline configured with any other encoding fails at startup rather than per frame.

The camera’s 4:2:2 chroma is decimated vertically to 4:2:0 by this conversion. That is unavoidable: the sensor cannot emit 4:2:0, SIPL cannot capture it, and nv12 is the only encoding both the H.264 encoder and ImageFormatConverterNode accept for multi-planar input.

Launch Files#

The sipl_camera.launch.py, sipl_stereo_camera.launch.py, and sipl_multi_camera.launch.py launch files conditionally add format conversion, rectification, H.264 encoding, and (for stereo) frame-pair gating nodes based on launch arguments. The format conversion and rectification nodes are from the isaac_ros_image_proc package, and the encoder node is from the isaac_ros_h264_encoder package.

When encoding_desired is set to a non-native format (anything other than nv12 or nv24), the launch file adds an ImageFormatConverterNode to convert the output.

When enable_rectify is set to true, the launch file adds a RectifyNode and automatically forces encoding_desired to rgb8 if a native format (nv12/nv24) was specified, because RectifyNode requires a standard image encoding.

When enable_encoding is set to true, the launch file adds an EncoderNode that H.264-encodes the camera output and publishes it on image_compressed (per eye for stereo). It consumes image_raw unless resizing is also enabled, in which case it consumes image_resize.

For mono, stereo, and multi-camera launches, enable_resize:=true adds a GPU ResizeNode per camera stream without first copying the native image through CPU memory. Mono publishes image_resize and camera_info_resize; stereo publishes those topics under left/ and right/; and multi-camera launches publish them under each <topic_namespace>/. The output defaults to 640 x 480 and can be changed with resize_width and resize_height. When resizing and encoding are both enabled, each encoder consumes image_resize and publishes image_compressed at the resized resolution.

Color Conversion Limitation#

When the launch files convert native nv12 output to a packed RGB or BGR format, ImageFormatConverterNode uses yuv_color_spec=bt709. SIPL ISP buffers are allocated with NvSciColorStd_REC709_ER, which is a full-range BT.709 color standard. CV-CUDA AdvCvtColor supports the BT.709 color matrix, but does not currently support the full-range REC709_ER variant. As a result, converted images can have slightly different luma contrast than a true full-range conversion. Native nv12 and nv24 output is unaffected.

If exact full-range color reproduction is required, subscribe to the native camera output and convert it with a pipeline that supports REC709_ER.

Verifying Stereo Camera Calibration#

Given the camera’s calibration data, you may use the epipolar test isaac_ros_rectify_stereo_epipolar_test.py in isaac_ros_image_proc package to validate that your stereo camera calibration produces accurately rectified images based on epipolar line tests.

Several files are required to run the test and should be placed in the rectify_stereo test cases directory of the isaac_ros_image_proc package.

${ISAAC_ROS_WS}/src/isaac_ros_image_pipeline/isaac_ros_image_proc/test/test_cases/rectify_stereo/

  1. Refer to the quickstart section for the isaac_ros_image_proc package on how to clone and build the package.

  2. Capture one left/right raw image pair of PNG files that contains a visible checkerboard pattern. For example, image_raw_right.png

  3. Create test configuration JSON files for the left and right camera respectively: image_raw_left.json and image_raw_right.json. These files should reference the PNG files and include the checkerboard inner-corner grid size (rows x columns). For example, image_raw_right.json

    Note

    The checkerboard size must use inner-corner counts (for example, a 10x7 square grid uses a 9x6 inner-corner size).

  4. Create camera info JSON files for left and right camera respectively: camera_info_left.json and camera_info_right.json. For example, camera_info_right.json

  5. Place all the PNG and JSON files in the rectify_stereo test cases directory of the isaac_ros_image_proc package:

    # From the workspace root
mkdir ${ISAAC_ROS_WS}/src/isaac_ros_image_pipeline/isaac_ros_image_proc/test/test_cases/rectify_stereo/sipl_stereo_camera
cp <your_files> ${ISAAC_ROS_WS}/src/isaac_ros_image_pipeline/isaac_ros_image_proc/test/test_cases/rectify_stereo/sipl_stereo_camera

  6. Build the isaac_ros_image_proc package after placing all the files:

    colcon build --packages-up-to isaac_ros_image_proc
source install/setup.bash

  7. Run the test:

    colcon test --packages-select isaac_ros_image_proc \
    --event-handlers console_direct+ \
    --ctest-args -R isaac_ros_rectify_stereo_epipolar_test

  8. Verify the test results. Passing the test indicates that the calibration accuracy is satisfactory. If the test fails, downstream packages that consume the rectified images may still function, but with degraded performance depending on your application’s requirements.

Note

A well-rectified pair has horizontal epipolar lines with sub-pixel mean error (less than 0.5 px) and max error under approximately 1-2 px.

Terminate a camera node with SIGINT rather than SIGKILL as killing it leaves the deserializer configured, and the next SetPlatformCfg then fails until the board is reset.

SIPL Camera Fails to Initialize: Missing Permissions#

Permission-related initialization errors include:

SIPL permission preflight failed: missing access for device group(s):
NvRmMemInitNvmap failed: error Permission denied
NvSciBufModuleOpen failed. nvSciStatus: 50

All transports require video permissions for imaging buffers and ISP access. GMSL also requires read/write access to host I2C and GPIO devices. The startup preflight requires access for all three device groups for every transport. Add your user to these groups on the Jetson host:

sudo usermod -aG video,i2c,gpio "$USER"

Verify the groups inside it with:

id -nG

Log out and back in for the new membership to take effect. The camera process needs these permissions in the environment where it runs including in the development container.

SIPL Camera Produces No Frames#

Symptom#

The SIPL camera node initializes (SIPL Camera initialized) but no frames arrive, and after first_frame_timeout_s (default 5 s) the node fails with:

[FATAL] [sipl_stereo_camera]: [left] No frames from sensor 0 within 5.0s. Verify the camera connection.

Solution#

There are many potential reasons the cameras fail to produce frames. Below are some possible reasons:

The Eagle CoE camera may flakily fail to produce frames after initializing but will recover after restarting the node.

Confirm that the GMSL board has 12 V power and that the camera is on the channel corresponding to the link_mask parameter.

For the Hawk GMSL camera, the Jetson might not be booted with the correct camera device tree. Re-run the readiness checks in the Hawk GMSL Stereo Camera Setup guide and confirm that v4l2-ctl --list-devices reports ar0234.

HSB fails to initialize with error “Address already in use”#

Symptom#

Unable to bind to initialize HSB and configure the HSB transport driver. You see the following error message:

[HSB] Error configuring driver: bind failed with errno=98: "Address already in use"

Solution#

Another Holoscan instance may still be running. Check and stop it:

ps aux | grep hololink

If there is output, kill the process if it is safe to do so:

kill -9 <pid>

  • Make sure to retrieve the CoE camera’s specific MAC and IP addresses. Refer to the Eagle CoE Stereo Camera Setup guide for instructions.

  • Use colon-separated hex format for MAC addresses: 8c:1f:64:6d:70:03

  • Use dotted decimal format for IP addresses: 192.168.1.2

  • Verify that the addresses match the camera documentation or EEPROM data.

HSB ID Mismatch#

Symptom#

No matching transport found for override: hsb_id=X
No matching camera found for override: hsb_id=X

Solution#

  1. Verify that the hsb_id parameter matches the platform configuration.

  2. Check the HSB ID in the camera system config.

  3. For VB1940, the default HSB ID is typically 0.

  4. Verify that the HSB ID matches across transport and camera configuration.
